# Flixy — Mobile Data Layer Contract

This document specifies the contract and patterns governing the data layer in the Flixy mobile application.

## Architectural Seam

Flixy is built with narrow **repository seams** for each persistence boundary. The current MVP uses Supabase only for Auth and watchlist rows; movie and TV metadata stays API-backed through TMDB.

*   **Supabase Client**: [`src/lib/supabase.ts`](file:///D:/Projects/Flixy/apps/mobile/src/lib/supabase.ts)
*   **Watchlist Boundary**: [`src/features/watchlist/store.ts`](file:///D:/Projects/Flixy/apps/mobile/src/features/watchlist/store.ts)
*   **Local MVP Boundary**: [`src/lib/localDb.ts`](file:///D:/Projects/Flixy/apps/mobile/src/lib/localDb.ts)
*   **Contract Rule**: Watchlist code must use `watchlistStore`; swipe writes must use the persistent `useSwipeQueue` (which synchronizes to Supabase and mirrors locally); profile and onboarding preferences use `localDb`; catalogue code must use the TMDB API client and must not write movie/TV rows from the client.
*   **Seam Benefit**: Auth/watchlist can run against Supabase in production while tests and unconfigured dev environments retain a local fallback.

## Data Model Schemas

### 1. Watchlist Item (`watchlist_items` / `LocalWatchlistItem` fallback)
Tracks the movies/tv shows saved or marked as watched by a user. In Supabase, `title_id` is a deterministic TMDB UUID generated by `src/lib/tmdb.ts`; it is not a foreign key to a persisted title row.
```typescript
type LocalWatchlistItem = {
  id: string;             // UUID
  user_id: string;        // Owner's User ID (or 'anon')
  title_id: string;       // Mapped TMDB UUID
  priority: 'top' | 'normal';
  position: number;       // Position in list (for manual ordering)
  added_at: string;       // ISO Timestamp
  watched_at: string | null;  // ISO Timestamp
  removed_at: string | null;  // ISO Timestamp (soft delete)
};
```

### 2. Swipe Event (`LocalSwipe`)
Tracks historical swipes for recommendation engine and telemetry.
```typescript
type LocalSwipe = {
  event_id: string;       // UUID
  user_id: string;        // User ID
  title_id: string;       // Mapped TMDB UUID
  direction: 'left' | 'right' | 'up' | 'down';
  occurred_at: string;    // ISO Timestamp
  session_id: string;     // Unique UUID per session
  deck_position: number;
  region: string;         // ISO Country Code
  filters_snapshot: {     // Filter state at the time of swipe
    services: string[];
    genres: string[];
  };
  is_undone?: boolean;    // Flagged true if reverted
};
```

### 3. User Preferences (`LocalPreferences`)
Stores selections made during onboarding.
```typescript
type LocalPreferences = {
  user_id: string;
  selected_services: string[];
  selected_genres: string[];
  notifications_enabled: boolean;
  onboarding_completed_at: string | null;
  cold_start_completed_at: string | null;
  updated_at: string;
};
```

### 4. User Profile (`LocalProfile`)
Stores region, language, display name, and avatar local paths.
```typescript
type LocalProfile = {
  id: string;
  region: string;         // E.g. 'US' or 'TR'
  language: string;       // E.g. 'en' or 'tr'
  name?: string;          // Display name
  avatar_url?: string;    // Local file:// URI path to persisted avatar
  created_at?: string;
};
```

## Persistence Interfaces

Every method returned by the store seams is asynchronous to keep network and local fallback behavior consistent:

```typescript
export const localDb = {
  // Swipe loop
  getSwipes(userId: string): Promise<LocalSwipe[]>;
  insertSwipe(swipe: LocalSwipe): Promise<void>;
  updateSwipe(eventId: string, updates: Partial<LocalSwipe>): Promise<void>;

  // Watchlist
  getWatchlist(userId: string): Promise<LocalWatchlistItem[]>;
  upsertWatchlistItem(item: Omit<LocalWatchlistItem, 'id'>): Promise<LocalWatchlistItem>;
  updateWatchlistItem(id: string, updates: Partial<LocalWatchlistItem>): Promise<void>;
  updateWatchlistItemByTitle(userId: string, titleId: string, updates: Partial<LocalWatchlistItem>): Promise<void>;

  // Preferences
  getPreferences(userId: string): Promise<LocalPreferences | null>;
  upsertPreferences(userId: string, updates: Partial<LocalPreferences>): Promise<LocalPreferences>;

  // Profiles & Handles
  getProfile(userId: string): Promise<LocalProfile | null>;
  upsertProfile(userId: string, updates: Partial<LocalProfile>): Promise<LocalProfile>;
  isHandleTaken(handle: string, excludeUserId: string): Promise<boolean>;

  // Credentials (Auth Mocking)
  getCredential(email: string): Promise<LocalCredential | null>;
  saveCredential(email: string, password: string, userId: string): Promise<void>;
  verifyCredential(email: string, password: string): Promise<boolean>;
  updatePassword(email: string, newPassword: string): Promise<void>;
  deleteCredential(email: string): Promise<void>;

  // Session Cleanup
  clearUserMemory(): Promise<void>;
};

export const watchlistStore = {
  getWatchlist(userId: string): Promise<LocalWatchlistItem[]>;
  upsertWatchlistItem(item: Omit<LocalWatchlistItem, 'id'>): Promise<LocalWatchlistItem>;
  updateWatchlistItem(id: string, updates: Partial<LocalWatchlistItem>): Promise<void>;
  updateWatchlistItemByTitle(userId: string, titleId: string, updates: Partial<LocalWatchlistItem>): Promise<void>;
};
```

## Storage Engine Invariants

1. **Isolation**: When rendering data in feature screens, always filter using the current authenticated user's `userId`.
2. **No Catalogue Persistence**: Mobile watchlist rows may store title IDs, but full movie/TV metadata is fetched from TMDB APIs at render time.
3. **Schema Versioning**: Stored JSON keys carry a `schema_version` wrapper (default version `1`). Legacy plain-array structures from prior iterations are parsed with a fallback parsing shim.
4. **Logout Cleanup**: On logout (`clearUserMemory`), local in-memory caches must be reset to empty and garbage-collected, preventing leaks between account swaps.
